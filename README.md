# cube-trainer

ルービックキューブを **「手順をなぞる」から「自分で判断できる」へ** 変えるための練習アプリ。

手元のキューブの状態を入れると、**いま CFOP のどの段階にいて、次に何をすればいいか**を、
テクニックの正式名称つきで示します。揃えたいだけのときは最短手順（2 フェーズ法・平均 21 手）に
切り替えられます。

- **公開先**: <https://takumayellow.github.io/cube-trainer/>
- **設計と今後の段階**: [takumayellow/rubik-solver#6](https://github.com/takumayellow/rubik-solver/issues/6)

---

## いま出来ること（Phase 1）

| 機能 | 中身 |
|---|---|
| 状態入力 | 展開図のマスをクリックして色を塗る / スクランブル / 手順文字列（`R U R' U'`）の適用 |
| 状態の検証 | 実物のキューブでは作れない状態（角 1 個のねじれ、辺 1 個の反転、2 個だけの入れ替え、色の枚数違い）を理由つきで拒否 |
| CFOP モード | Cross → F2L → OLL → PLL のどこにいるかを判定。F2L は 4 スロットそれぞれの状況（ペアが上段にある / 埋まっている）と、次に狙うスロットの角と辺をハイライト |
| テクニック辞典 | いまの段階で使うものを、**手順・何をするか・使う場面**の 3 点セットで表示 |
| 最短モード | 2 フェーズ法で解を求め、1 手ずつ / 最後まで 進めながら展開図で確認 |

手を動かすと判定はその場で更新されるので、**自分で回しながら「いまどの段階か」を確認する**使い方が
本命です。

## 動かし方

ビルド不要の静的サイトです。`index.html` をブラウザで開くだけで動きます。

```bash
node test/run.js          # 状態モデル・妥当性検証・2 フェーズ法・フェーズ判定・手順の性質
python test/ui_smoke.py   # 実ブラウザでの操作確認（要 playwright）
```

`test/run.js` は辞典に載せた手順も検証します。「OLL 手順」と書いたものが本当に第 2 層を壊さないか、
「PLL 手順」が上面を壊さないか、位数（T-perm は 2 回、Ua-perm は 3 回で元に戻る）が合っているかを、
フェーズ判定器そのもので確かめています。

## ファイル構成

```
cube-trainer/
├── index.html
├── css/style.css
├── js/
│   ├── cube.js        # 状態モデル（6 面 × 9 マス）と面回転
│   ├── cubie.js       # 面の色 ⇄ 駒（角 8 / 辺 12）の変換、状態の妥当性検証
│   ├── two-phase.js   # Kociemba 2 フェーズ法ソルバー
│   ├── cfop.js        # いまどのフェーズか、次に狙う駒はどれか
│   ├── glossary.js    # テクニックの名称・手順・何をするか
│   ├── net.js         # 展開図の描画とクリック
│   └── app.js         # 画面
└── test/
    ├── run.js
    └── ui_smoke.py
```

`cube.js` と `two-phase.js` は [takumayellow/rubik-solver](https://github.com/takumayellow/rubik-solver)
の Web 版から移したものです。手順は公知のアルゴリズムを自分で書き起こしたもので、既存サイトの
手順表や画像は使っていません。
