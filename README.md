# cube-trainer

ルービックキューブを **「手順をなぞる」から「自分で判断できる」へ** 変えるための練習アプリ。

手元のキューブの状態を入れると、**いま何をすればいいかだけ**を、実際に回す手順と
テクニックの正式名称つきで示します。全ケースの一覧は出しません。揃えたいだけのときは
最短手順（2 フェーズ法・平均 21 手）に切り替えられます。

- **公開先**: <https://takumayellow.github.io/cube-trainer/>（PC 版） /
  <https://takumayellow.github.io/cube-trainer/app.html>（スマホ版）
- **設計と今後の段階**: [takumayellow/rubik-solver#6](https://github.com/takumayellow/rubik-solver/issues/6)

## いま出来ること

| 機能 | 中身 |
|---|---|
| 状態入力 | **カメラ / 写真で 6 面を読み取る** / 展開図のマスをクリックして色を塗る / スクランブル / 手順文字列（`R U R' U'`、空白なしの `RUR'U'` も可）の適用 / キーボード（`R` で R、`Shift`+`R` で R'） |
| 状態の検証 | 実物のキューブでは作れない状態（角 1 個のねじれ、辺 1 個の反転、2 個だけの入れ替え、色の枚数違い）を理由つきで拒否 |
| CFOP モード | Cross → F2L → OLL → PLL のどこにいるかを判定し、**その状態で今やること 1 つだけ**を、回す手順つきで出す。対象の駒はハイライト |
| 手順の出どころ | Cross と F2L は**探索**（すでに揃えた部分を壊さないことを条件に入れた最短手順）。OLL / PLL は手持ちの手順を実際に当てて、形が合うものを名前つきで提示 |
| テクニック辞典 | いま出ている手順について、**名前・何をするか・使う場面**。全ケースの一覧はたたんである |
| 3D ビュー | 展開図と同じ状態を立体で表示（ドラッグで回転）。ハイライトも連動 |
| 最短モード | 2 フェーズ法で解を求め、1 手ずつ / 最後まで 進めながら展開図で確認 |

### 持ち方

**白を下・緑を手前**に持った標準の配置で表示します（上面は黄色、左が赤、右が橙）。CFOP は
クロスを底面に作るので、この向きだと画面と手元のキューブが同じ「白クロス」になります。

### カメラ読み取り

U → R → F → D → L → B の順に、持ち方の指示つきで 6 面を撮ります。枠の中が読み取り範囲そのもの
（プレビューは正方形で、映像の中央正方形をそのまま表示している）です。

色の判定はマス単位のしきい値ではなく、**54 マスをまとめてクラスタリング**します。1 色ちょうど 9 マス
という制約を守ったまま、6 つのクラスタを 6 色に一括で対応づけるので、部屋の照明でどちらへ転んでも
6 色が同じだけずれて打ち消し合います。判定が際どかったマスは読み取り後に名指しで報告し、そのまま
塗り直せるように色塗りモードへ切り替わります。

カメラが使えない環境（許可なし・カメラなし）では、同じ流れで**写真ファイルを 1 面ずつ**選べます。

手を動かすと判定はその場で更新されるので、**自分で回しながら「いまどの段階か」を確認する**使い方が
本命です。

### スマホ版（`app.html`）

片手にキューブ、片手にスマホで使う前提の画面です。判定・探索・読み取りは PC 版と同じコードで、
画面だけが違います。下のタブで 4 画面を切り替えます。

| タブ | 中身 |
|---|---|
| 次の一手 | いまの段階（Cross / F2L / OLL / PLL）と、次に回す 1 手を大きく表示。回したら画面をタップすると次の手へ進む |
| 読み取り | カメラで 6 面を撮る（写真ファイルも可）。際どいマスは名指しで出し、パレットで塗り直してから判定へ渡す |
| 最短 | 2 フェーズ法の解を 1 手ずつ / 自動再生で進める。手順のチップから途中へ飛べる |
| 辞典 | 今回の解き方で実際に使ったテクニックだけを、回した手順つきで残す。いまのものと次に来るものも出す |

- **ヒントの段階**: L0 場所だけ → L1 対象の駒を光らせる → L2 見分け方 → L3 手順。L2 までは「手順を見る」で
  そのときだけ手順を開ける。
- **画面で回す**: 実物のキューブが手元に無くても、3D キューブ（ドラッグで向きを変えられる）と 18 個の
  ムーブパッドで同じ案内をたどれる。案内中の手はパッドで光り、押すとそのまま 1 手進む。
  手順を文字で打ち込む（`R U R' U'`）か、キーボードの `R` / `Shift`+`R` でも回せる。
- **手の言い方**: `R'` のような記号に「右の面を手前へ回す」のような言い方を添える（白を下・緑を手前の
  持ち方での向き）。PC 版の案内にも同じ言い方を出している。
- 状態とヒントの段階は端末に保存され、開き直しても続きから始まる。

## 動かし方

ビルド不要の静的サイトです。`index.html` をブラウザで開くだけで動きます。

```bash
node test/run.js          # 状態モデル・妥当性検証・2 フェーズ法・フェーズ判定・手順の性質
python test/ui_smoke.py   # 実ブラウザでの操作確認（要 playwright / pillow）
python test/app_smoke.py  # スマホ版の操作確認（390 / 360 px。URL を渡すと公開版を確かめる）
```

`test/run.js` は OLL 216 通り・PLL 288 通りの全ケースを手持ちの手順で閉じられるか、案内どおりに
回すとスクランブルが完成に到達するか、写真からの色読み取りが照明のかぶり（電球色・薄暗い部屋・
昼白色）込みで元の状態に戻るかまで確かめます。辞典に載せた手順も検証します。「OLL 手順」と書いたものが本当に第 2 層を壊さないか、
「PLL 手順」が上面を壊さないか、位数（T-perm は 2 回、Ua-perm は 3 回で元に戻る）が合っているかを、
フェーズ判定器そのもので確かめています。

## ファイル構成

```
cube-trainer/
├── index.html         # PC 版
├── app.html           # スマホ版
├── css/
│   ├── style.css      # PC 版
│   └── app.css        # スマホ版
├── js/
│   ├── cube.js        # 状態モデル（6 面 × 9 マス）と面回転
│   ├── cubie.js       # 面の色 ⇄ 駒（角 8 / 辺 12）の変換、状態の妥当性検証
│   ├── two-phase.js   # Kociemba 2 フェーズ法ソルバー
│   ├── cfop.js        # いまどのフェーズか、次に狙う駒はどれか
│   ├── search.js      # 駒モデルでの IDA* 探索（Cross / F2L の手順を作る）
│   ├── algs.js        # OLL / PLL の手順表と、実際に当てて形を見分ける処理
│   ├── step.js        # いまの状態で「次にやること 1 つ」を決める
│   ├── glossary.js    # テクニックの名称・手順・何をするか
│   ├── net.js         # 展開図の描画とクリック
│   ├── cube3d.js      # 立体表示（CSS 3D・ドラッグで回転）
│   ├── scan.js        # 撮った色 → 状態（54 マスのクラスタリング）
│   ├── camera.js      # 6 面の撮影フロー（カメラ / 写真ファイル）
│   ├── move-words.js  # 手の言い方（「右の面を手前へ回す」）、打ち込んだ手順とキーの読み取り
│   ├── app.js         # PC 版の画面
│   └── mobile/        # スマホ版の画面
│       ├── store.js       # 状態・ヒントの段階・使ったテクニックの保存
│       ├── ui.js          # 展開図・見出しなどの部品
│       ├── coach.js       # 次の一手（画面で回すモード込み）
│       ├── scanner.js     # 読み取り
│       ├── shortest.js    # 最短
│       ├── dictionary.js  # 辞典
│       └── main.js        # タブの切り替え
└── test/
    ├── run.js
    ├── ui_smoke.py
    └── app_smoke.py
```

`cube.js` と `two-phase.js` は [takumayellow/rubik-solver](https://github.com/takumayellow/rubik-solver)
の Web 版から移したものです。手順は公知のアルゴリズムを自分で書き起こしたもので、既存サイトの
手順表や画像は使っていません。
